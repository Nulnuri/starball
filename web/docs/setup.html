스타볼 알림 봇 설치

LG 홈경기가 있는 날 아침, 스타볼 추천 항목이 폰 알림으로 옵니다. 컴퓨터를 켜둘 필요가 없습니다. 깃헙을 처음 써도 따라올 수 있게 썼고, 전부 웹 화면에서 끝납니다. 30분쯤 걸립니다.

이 흐름에 개인 컴퓨터가 없습니다. 계산은 깃헙 서버에서 일어나고, 폰은 결과만 받습니다. 알림만으로도 입력은 됩니다 — 앱은 근거를 다시 보거나 지난 성적을 확인할 때 씁니다.

준비물

  • 깃헙 계정 — 없으면 만듭니다. 무료입니다.
  • 스마트폰 — 안드로이드 또는 아이폰.
  • 전달받은 파일들 — starball-lab 폴더 안에 있습니다.

비용은 들지 않습니다. 저장소는 공개(Public)로 만듭니다 — 깃헙 페이지 무료 배포가 공개 저장소에서만 되기 때문입니다. 대신 알림 토픽 이름은 비밀로 등록하니 남이 볼 수 없습니다(5단계).

설치 절차

  1. 1

    깃헙 계정 만들기 약 5분

    github.com/signup 에서 가입합니다. 이메일 인증까지 마치면 됩니다. 이미 계정이 있으면 이 단계는 넘어갑니다.

  2. 2

    저장소 만들기 약 2분

    오른쪽 위 + → New repository 를 누릅니다.

    • Repository name: starball (다른 이름도 됩니다)
    • Public 을 선택합니다 — 무료 계정은 공개 저장소에서만 웹앱을 배포할 수 있습니다
    • 나머지는 건드리지 않고 Create repository
    공개로 둬도 괜찮은 이유

    들어가는 건 프로그램 코드와 경기 예측뿐입니다. 개인 정보는 없습니다. 알림 토픽 이름만은 코드가 아니라 비밀 값(Secret)으로 따로 등록하니(5단계) 공개되지 않습니다.

  3. 3

    파일 올리기 약 4분

    저장소 화면에서 Add file → Upload files 를 누르고, 전달받은 폴더에서 아래를 끌어다 놓습니다. web 은 폴더째 끌면 됩니다.

    올릴 것
    starball_predictor.py     예측 본체
webdata.py                웹앱 데이터 생성·채점
backtest.py               webdata 가 채점 규칙을 여기서 가져다 씁니다
requirements.txt          필요한 라이브러리 목록
park_factors.json         구장·불펜 보정값
base_rates.json           리그 기저 분포
web/                      폴더째 (웹앱 화면과 데이터)

    다 올렸으면 아래 Commit changes 를 누릅니다.

    보정값 두 개를 빠뜨리지 마세요

    park_factors.json 과 base_rates.json 이 없으면 프로그램은 돌아가지만 정확도가 떨어진 채로 동작합니다. 빠지면 실행 기록에 경고가 남습니다.

    올리지 않는 것

    today.json(폴더 바깥에 있는 것), gamelog_2026.json, .cache, __pycache__, design, .html 문서들은 빼둡니다. 없어도 되고, 있으면 지저분해집니다.

  4. 4

    실행 시간표 파일 만들기 약 5분

    이 파일만은 끌어다 놓지 말고 직접 만듭니다. 폴더 이름이 점으로 시작해서 (.github) 브라우저가 업로드에서 빼먹는 일이 있습니다.

    Add file → Create new file 을 누르고, 파일 이름 칸에 아래를 그대로 칩니다. 슬래시를 치면 폴더가 자동으로 생깁니다.

    파일 이름 칸에 입력
    .github/workflows/starball.yml

    그리고 아래 내용을 붙여넣고 Commit changes 를 누릅니다.

    .github/workflows/starball.yml
    name: LG 스타볼 예측 알림

on:
  schedule:
    # 깃헙 크론은 UTC 기준이다. 01:00 UTC = 한국시간 오전 10시.
    # 한국시간으로 바꾸려면 원하는 시각에서 9시간을 빼면 된다.
    #   오전 10시(KST) → 01:00 UTC   |   오후 2시(KST) → 05:00 UTC
    # 부하에 따라 5~30분 밀릴 수 있다. 경기가 18:30이라 여유는 충분하다.
    - cron: '0 1 * * *'

    # 마감 임박 알림. 아침 알림은 경기 8시간 전에 와서 저녁이면 묻힌다.
    # 경기 시각이 14:00 / 17:00 / 18:30 세 종류라, 각 경기가 시작 2시간쯤
    # 전에 딱 한 번 걸리도록 세 번 돈다(KST 12:00 / 15:00 / 16:30).
    # 해당 구간이 아니면 스크립트가 조용히 종료한다 — 알림이 두 번 가지 않는다.
    - cron: '0 3 * * *'      # 12:00 KST → 14:00 경기
    - cron: '0 6 * * *'      # 15:00 KST → 17:00 경기
    - cron: '30 7 * * *'     # 16:30 KST → 18:30 경기

  # Actions 탭에서 손으로 눌러 즉시 실행할 수 있게 해둔다.
  # 처음 설정한 뒤 이걸로 한 번 테스트하는 것을 권한다.
  workflow_dispatch:

# 동시에 두 번 돌아 알림이 중복 발송되는 것을 막는다.
concurrency:
  group: starball
  cancel-in-progress: false

# 웹앱 파일을 깃헙 페이지로 올리기 위해 필요하다.
permissions:
  contents: write
  pages: write
  id-token: write

jobs:
  predict:
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - uses: actions/checkout@v4
        with:
          # 얕은 클론이면 아래 rebase 가 실패한다. 저장소가 작으니 전부 받는다.
          fetch-depth: 0

      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          cache: pip

      - run: pip install -r requirements.txt

      - name: 알림 토픽 확인
        # 공개 저장소라 코드에 박힌 기본 토픽은 누구나 볼 수 있다.
        # 그 토픽으로 발송하면 남이 가짜 알림을 보낼 수 있으므로,
        # Secret 을 반드시 등록하게 막는다.
        env:
          NTFY_TOPIC: ${{ secrets.NTFY_TOPIC }}
        run: |
          if [ -z "$NTFY_TOPIC" ]; then
            echo "::error::NTFY_TOPIC Secret 이 없습니다. 저장소 Settings →"
            echo "::error::Secrets and variables → Actions 에서 등록하세요."
            echo "::error::공개 저장소에서 기본 토픽을 쓰면 남이 알림을 보낼 수 있습니다."
            exit 1
          fi
          echo "토픽 Secret 확인됨 (${#NTFY_TOPIC}자)"

      - name: 마감 임박 알림
        # 아침 실행(01:00 UTC)이 아닐 때만 돈다. 구간 밖이면 스크립트가
        # 스스로 건너뛰므로 여기서 시각을 따로 따지지 않는다.
        if: github.event.schedule != '0 1 * * *'
        env:
          NTFY_TOPIC: ${{ secrets.NTFY_TOPIC }}
        run: |
          python starball_predictor.py --reminder
          echo "마감 임박 알림 단계 완료"

      - name: 예측 실행 및 푸시 발송
        # 아침 실행에서만 전체 예측을 보낸다.
        if: github.event.schedule == '0 1 * * *' || github.event_name == 'workflow_dispatch'
        env:
          # 저장소 Settings → Secrets and variables → Actions 에 등록한 값.
          # 등록하지 않으면 스크립트 기본 토픽으로 발송된다.
          NTFY_TOPIC: ${{ secrets.NTFY_TOPIC }}
        run: |
          set +e
          # --home-only 를 쓰면 안 된다. 스타볼 미션은 원정 경기에도 열린다
          # (2026-08-28 LG@롯데 원정 경기에서 확인). 잔여 시즌 기준으로
          # 원정이 54%라, 켜두면 절반 이상을 놓친다.
          python starball_predictor.py --ntfy
          code=$?
          set -e
          echo "종료 코드: $code"
          case $code in
            0)
              echo "정상 종료 (예측 발송 완료, 또는 홈경기가 아니거나 경기 없는 날)"
              exit 0 ;;
            75)
              echo "::notice::선발 예고 전이라 예측을 건너뛰었습니다. 실패가 아닙니다."
              exit 0 ;;
            *)
              echo "::error::예측 실패 (코드 $code)"
              exit $code ;;
          esac

      - name: 웹앱 데이터 갱신 (지난 경기 채점 + 오늘 예측)
        # 알림이 실패해도 웹앱은 갱신한다. 둘은 독립적이다.
        # 다만 하루 한 번(아침)이면 충분하다 — 마감 알림 실행에서 또 돌리면
        # 네이버에 하루 4배로 요청하면서 얻는 게 없다.
        if: always() && (github.event.schedule == '0 1 * * *' || github.event_name == 'workflow_dispatch')
        run: |
          set +e
          python webdata.py both
          echo "webdata 종료 코드: $?"
          exit 0

      - name: 갱신된 데이터 커밋
        if: always() && (github.event.schedule == '0 1 * * *' || github.event_name == 'workflow_dispatch')
        run: |
          git config user.name  "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"

          # 파일을 하나씩 지정하면 없을 때 git add 가 실패해 잡 전체가 죽는다.
          # 디렉터리째 넘기면 있는 것만 담는다.
          git add -A web

          # 바뀐 게 없으면 커밋하지 않는다(휴식일에 빈 커밋이 쌓이는 것 방지).
          if git diff --staged --quiet; then
            echo "변경 없음 — 커밋 건너뜀"
            exit 0
          fi
          git commit -m "데이터 갱신 $(date -u +%Y-%m-%d)"

          # 사용자가 깃헙 웹에서 파일을 고쳤으면(문항 정의 등) push 가 거부된다.
          # 한 번 받아서 얹고 다시 시도한다.
          for i in 1 2 3; do
            if git push; then
              echo "push 성공"
              exit 0
            fi
            echo "push 거부 — 원격 변경을 받아 다시 시도 ($i/3)"
            git pull --rebase --autostash origin "${GITHUB_REF_NAME}" || exit 1
          done
          echo "::error::push 를 3번 시도했으나 실패했습니다."
          exit 1

      - name: 깃헙 페이지에 웹앱 배포
        if: always() && (github.event.schedule == '0 1 * * *' || github.event_name == 'workflow_dispatch')
        uses: actions/upload-pages-artifact@v3
        with:
          path: web

  deploy:
    needs: predict
    # 아티팩트를 올린 실행에서만 배포한다. 마감 알림 실행에는 올릴 게 없다.
    if: always() && (github.event.schedule == '0 1 * * *' || github.event_name == 'workflow_dispatch')
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
  5. 5

    알림 토픽 이름 등록하기 약 3분

    토픽은 알림이 흐르는 채널 이름입니다. 폰에서 이 이름을 구독하면 알림이 옵니다. 남이 맞히기 어려운 이름으로 정하세요. 이유는 함정 항목에 있습니다.

    토픽 이름 예시 — 뒤에 아무 문자나 섞습니다
    lg-starball-k7m2x9q4

    저장소 Settings → 왼쪽 Secrets and variables → Actions → New repository secret 을 누르고:

    칸넣을 값
    NameNTFY_TOPIC
    Secret위에서 정한 토픽 이름

    Add secret 을 누르면 끝입니다.

  6. 6

    웹앱 배포 켜기 약 2분

    알림만 쓸 거면 이 단계는 건너뛰어도 됩니다. 앱 화면까지 쓰려면 켜세요.

    저장소 Settings → 왼쪽 Pages → Source 를 GitHub Actions 로 바꿉니다. (기본값은 “Deploy from a branch”인데, 그대로 두면 안 됩니다.)

    주소는 자동으로 정해집니다

    https://<아이디>.github.io/starball/ 형태입니다. 7단계에서 첫 실행이 끝나면 Actions 기록에 실제 주소가 찍힙니다. 참고로 이 문서를 만든 저장소는 starball-9oj.pages.dev 에서도 같은 내용을 서비스합니다 (Cloudflare Pages, 주소가 짧아서 폰에 넣기 편합니다).

  7. 7

    첫 실행 약 2분

    아침까지 기다릴 필요 없습니다. 저장소 위쪽 Actions 탭 → 왼쪽 LG 스타볼 예측 알림 → 오른쪽 Run workflow → 초록 Run workflow 버튼을 누릅니다.

    2분쯤 뒤 목록에 새 실행이 생기고, 눌러보면 진행 상황이 보입니다.

    성공 판정

    초록 체크 표시가 뜨면 성공입니다. LG 경기가 있는 날이면 폰에 알림이 와 있고, 웹앱 주소도 만들어졌습니다. 경기 없는 날이면 알림 없이 초록 체크만 뜨는데 이것도 정상입니다.

    빨간 X 에 “NTFY_TOPIC Secret 이 없습니다”

    5단계를 건너뛰었거나 이름을 NTFY_TOPIC 이 아닌 걸로 등록한 경우입니다. 다시 등록하고 실행하면 됩니다.

  8. 8

    폰 설정 약 4분

    알림 받기 — 앱스토어나 플레이스토어에서 ntfy 를 검색해 설치합니다. 무료입니다.

    • 앱을 열고 + 버튼을 누릅니다
    • Topic name 칸에 5단계에서 정한 토픽 이름을 정확히 칩니다
    • Subscribe 를 누릅니다
    한 글자라도 다르면 안 옵니다

    깃헙 Secret 에 넣은 이름과 폰에서 구독한 이름이 완전히 같아야 합니다. 대소문자, 하이픈까지 그대로여야 합니다.

    앱 화면 추가하기 — 6단계를 켰다면, 폰 브라우저로 웹앱 주소를 엽니다.

    • 아이폰: 사파리에서 열고 공유 버튼 → 홈 화면에 추가
    • 안드로이드: 크롬에서 열고 우측 상단 ⋮ → 홈 화면에 추가

    홈 화면 아이콘으로 열면 주소창 없이 앱처럼 뜹니다. 설치할 것도, 스토어 심사도 없습니다.

도착하는 알림

접힌 상태에서 첫 줄만 봐도 판단이 서게 만들었습니다. 펼치면 스타볼 입력 순서 그대로 나열됩니다.

ntfy·오전 10:04
⚾ 오늘의 LG 스타볼 예측 추천
승패 승 · LG선발 0~1점 · 홈런 1~2개 NC@LG 잠실 18:30 · 예상 6.1-4.7 · 신뢰도 보통 ■ 이대로 찍으세요 승패 → 승 (59%) 점수차 → 4점 차 이상 (51%) 홈런 → 1~2개 (53%) LG선발 → 0~1점 (60%) 득점 → 9점 이상 (64%) ■ 반반 — 아무거나 (모델이 못 가림) 상대선발 2~3점(35%) · 안타 16~20개(37%)
스타볼 입력하러

“반반” 구역은 그대로 믿지 마세요. 1위와 2위 확률 차이가 5%p도 안 되는 항목입니다. 모델이 못 가린다는 뜻이라 아무거나 찍어도 같습니다. 확신 있는 항목과 섞어놓으면 다 맞는 것처럼 보여서 일부러 갈라놨습니다.

아래 스타볼 입력하러 버튼을 누르면 LG 트윈스 스타볼 페이지로 바로 갑니다.

알림은 하루 두 번

시각 내용
오전 10시 그날 예측 전체. 세 값과 확률, 근거 요약.
경기 2시간 전 짧은 재알림 — 값 세 개와 아직 안 넣었으면 지금.
경기 시각이 달라도 알아서 맞춥니다

LG 경기는 14시·17시·18시 30분에 시작합니다. 워크플로가 낮에 세 번 확인하면서 그 경기가 2시간쯤 남았을 때만 재알림을 보냅니다. 나머지 실행은 조용히 종료하니 알림이 두 번 겹치지 않습니다.

앱 화면

알림만으로도 입력은 됩니다. 앱은 알림이 지나간 뒤와 내가 얼마나 맞히고 있는지를 위해 있습니다.

화면 쓰임

알아둬야 할 함정

함정 1 · 60일 방치되면 멈춥니다

저장소에 아무 변경 없이 60일이 지나면 깃헙이 자동 실행을 끕니다. 메일로 알려주긴 하는데 놓치기 쉽습니다. 비시즌이 11월부터 2월까지 넉 달이라 반드시 걸립니다.

대처: 매년 3월 개막 전에 Actions 탭을 열어보고, 꺼져 있으면 안내 문구의 Enable workflow 를 눌러 다시 켭니다.

함정 2 · 토픽은 비밀번호가 없습니다

ntfy 토픽은 이름만 알면 누구나 구독할 수 있고, 발행도 할 수 있습니다. 남이 내 토픽으로 엉뚱한 알림을 보낼 수 있다는 뜻입니다.

대처: 토픽 이름에 맞히기 어려운 문자를 섞고, 반드시 Secret 으로만 등록합니다. 코드나 파일에 적어 넣으면 공개 저장소라 그대로 노출됩니다. Secret 을 빠뜨리면 실행이 아예 실패하도록 막아뒀으니, 실수로 기본 토픽이 쓰이는 일은 없습니다.

함정 3 · 시간이 정확하지 않습니다

깃헙 무료 자동 실행은 서버 부하에 따라 5~30분씩 밀립니다. 10시 예약이 10시 25분에 돌 수 있습니다. 경기가 저녁 6시 30분이라 실제로는 문제되지 않습니다.

함정 4 · 선발 예고 전이면 건너뜁니다

예측에는 양 팀 선발 투수가 필요합니다. 선발 예고는 보통 전날 오후에 나오는데, 어떤 이유로 늦어지면 그날은 알림이 오지 않고 실행 기록에 안내 문구만 남습니다. 실패가 아니라 건너뛴 것입니다.

안 될 때

증상원인과 해결
초록 체크인데 알림이 안 온다 토픽 이름이 어긋났을 가능성이 가장 큽니다. 깃헙 Secret 값과 폰 구독 이름을 다시 대조하세요. 또는 그날이 LG 원정 경기일 수 있습니다 — 실행 기록을 열면 어느 쪽인지 적혀 있습니다.
빨간 X 표시가 뜬다 실행 기록을 눌러 ::error:: 로 시작하는 줄을 찾습니다. 네이버 쪽 응답 형식이 바뀌면 이렇게 됩니다. 그 줄을 그대로 전달해주세요.
Actions 탭이 비어 있다 4단계 파일 경로가 틀렸을 때 생깁니다. 반드시 .github/workflows/starball.yml 이어야 합니다. 맨 앞의 점을 빼먹지 않았는지 확인하세요.
알림이 하루에 두 번 온다 수동 실행(Run workflow)을 누른 날은 자동 실행과 합쳐 두 번 옵니다. 정상입니다.
실행 시간을 바꾸고 싶다 starball.yml 의 cron: '0 1 * * *' 에서 숫자 1이 UTC 시각입니다. 원하는 한국 시각에서 9를 뺀 값을 넣습니다. 오후 2시로 바꾸려면 '0 5 * * *' 입니다.

예측은 네이버 스포츠에 공개된 경기 기록으로 계산한 확률입니다. 결과를 보장하지 않습니다. 스타볼 입력은 알림을 보고 직접 하도록 만들었습니다 — 자동 입력은 이벤트 약관에 걸릴 수 있어 넣지 않았습니다.
